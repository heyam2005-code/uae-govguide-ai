# نص Demo مقترح (4–6 دقائق)

**0:00–0:40 — المشكلة:** توجيه المواطنين والمقيمين نحو الخدمة والجهة الصحيحة أكثر تعقيدًا من مجرد إيجاد مبنى على الخريطة. تختلف الشروط حسب الفئة والعمر والوثائق وطريقة التقديم.

**0:40–1:15 — الحل:** UAE GovGuide AI هو نموذج مستقل يوفر حوارًا متتابعًا، معرفة حكومية موثقة، قواعد شروط الأهلية، مراكز مرشّحة، وسجل قرارات قابل للمراجعة.

**1:15–2:30 — تجربة أساسية:** افتحي `/assistant` ثم «محادثة جديدة». اكتبي: «أنا مواطن إماراتي، في دبي بمنطقة البرشاء، وبدي أجدد هويتي. وين أراجع وشو الإجراءات المطلوبة؟». أجيبي بالترتيب: `29 سنة`, `شهر`, `12`, `نعم`, `عاجلة`. أظهري توصية البرشاء وأسبابها ورابط ICP وتنبيه تأكيد الخدمة العاجلة.

**2:30–3:40 — السيناريو المتسلسل:** محادثة جديدة أو محاكاة في `/`. أدخلي جواز صالحًا لشهر فقط في الطلب؛ أظهري كيف يمنع الوكيل حالة ready ويقترح التحقق من تجديد الهوية والجواز معًا بدل إعطاء طمأنة مضللة.

**3:40–4:35 — البيانات والسياسات:** انتقلي إلى `/locator` وافتحي مراكز دبي. فسّري أن ترتيب البرشاء مبني على تطابق المنطقة والفئة والخدمة وليس المسافة، وأن المركز ذي البيانات غير المؤكدة يُستبعد. افتحي مصادر ICP.

**4:35–5:15 — المساءلة:** اعرضي سجلات القرارات، وخطوات البيانات -> RAG -> policy checks -> recommendation. قولي إن معلومات الهوية الحساسة غير مطلوبة وإن النموذج السحابي اختياري وغير مفعّل افتراضيًا.

**5:15–5:45 — القياس والحدود:** عرض نتائج 69 اختبار كود و36 حالة تركيبية؛ لا تدّعي دقة 100% في الواقع. اذكري أولويات التحسين: بيانات حيّة موثقة، توسيع التغطية، وإجراءات مراجعة بشرية لحالات تعارض المصادر.

**ملحوظة تصوير:** استخدمي بيانات تجريبية فقط. لا تُظهري مفاتيح API أو حسابات شخصية. في حال تغيّر مسار الواجهة، استندي إلى اختبار شاشة موثّق بدل ادعاء وظيفة غير موجودة.
